## Analytics and media kit

The Analytics page reads stored posts and snapshots (`GET /analytics`). Refresh metrics calls `POST /analytics/sync` with `force: true` and walks every stored post, not the first 40. A failed metric is skipped. It does not drop the rest of that post.

YouTube lifetime views, likes and comments come from `videos.list`. The last 28 days ending two days ago, when `yt-analytics.readonly` is on the saved login, also stores minutes watched, period views, average view duration and percent, shares, subscribers gained and lost, and thumbnail impressions when YouTube returns them. A YouTube connect always requests that analytics scope as well as `youtube.readonly`. Integrations → Reconnect keeps comments and uploads and sends the owner back to Google.

Instagram likes and comments come from the media object (`like_count`, `comments_count`). Insights use only metrics that media type accepts: a photo is not asked for `views`. Reels also store average and total watch time. The account stores reach, views, accounts engaged and interactions for Instagram's own last 28 days, plus follower demographics. `instagram_business_manage_insights` is already required for those.

Facebook reactions, comments and shares use the post object. `read_insights` adds `post_media_view`, clicks, video views, average watch time and reaction types, plus the latest day of page media views, post engagements and page views. Followers use `page_follows`. Country and city use `page_follows_country` and `page_follows_city`. `page_fans` is not requested. Adding a permission in the Meta app does not change the saved login until Reconnect.

Extra post figures live in `publication_metrics_snapshots.provider_meta.metrics`. A new snapshot merges into `latest_stats` and does not replace a stored like count with null. Breakdown rows stay in `account_metric_snapshots.detail`. TikTok analytics are not collected. The public kit is `/kit/:slug`, filled only from the published projection. Migrations `0033_analytics_kit` and `0034_analytics_detail`. Rebuild `docker compose up -d --build --force-recreate api web worker`.

## Snapchat

Integrations → Snapchat uses the Public Profile API, not Snap Kit Login. Connect opens a checkbox and, when Public Profile is checked, `https://accounts.snapchat.com/login/oauth2/authorize` with `scope=snapchat-profile-api`. Leaving the box off does not open Snapchat. The callback is `{APP_BASE_URL}/api/v1/integrations/snapchat/callback`, or `SNAPCHAT_REDIRECT_URI` when that is set. Tokens are encrypted. A 403 from Snapchat is saved as partial and says the app is not allowlisted. Profile and story listing are recorded only after those calls succeed. Posting and analytics stay off. Rebuild `docker compose up -d --build --force-recreate api web`.

## Threads

Threads is a separate login on the same Meta app. Facebook Page permissions do not grant it. Connect is Integrations → Connect Threads, which opens `https://threads.net/oauth/authorize`. The callback is `{APP_BASE_URL}/api/v1/integrations/threads/callback`. Uninstall is `POST /api/v1/integrations/threads/deauthorize` and drops the token. Data deletion is `POST /api/v1/integrations/threads/data-deletion`: it checks Meta's `signed_request` with the Threads app secret, deletes the token and imported Threads posts, and returns `{ url, confirmation_code }`. The status page is `GET` that same path with `?code=`. Neither URL needs a login. Connect, Reconnect, and Enable Page videos for Facebook, Instagram, Threads, and TikTok open a checklist (`apps/web/src/components/permission-picker.tsx`). The login asks only for the checked permissions, and the required one stays on. Already granted permissions start checked. A permission Meta has not approved should be left off, because one rejected permission fails the whole login. The catalog is `packages/domain/src/oauth-permissions.ts`. Sending, replying, and deleting stay off until the owner confirms that one action. A confirmed Publish or Schedule sends one JPEG, PNG, MP4, or MOV. Threads downloads that file from the public https address. The post text is at most 500 characters, with one optional topic, who can reply, and the AI label. A link card is only for a text-only post, so a file post does not attach one. The app id and secret fall back to `FACEBOOK_APP_ID` / `FACEBOOK_APP_SECRET` unless `THREADS_APP_ID` and `THREADS_APP_SECRET` are set. Import posts runs after the connection is linked to a Channels account (`POST /connections/:id/sync`). Insights (views, likes, replies, reposts, quotes, shares, followers) run on Analytics → Refresh metrics. Code: `packages/connectors/src/meta/threads.ts`. Rebuild `docker compose up -d --build --force-recreate api web worker`.
