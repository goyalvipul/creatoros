# Native Agent Studio release candidate (PR #27)

## Application implementation

The existing private ChatGPT connector, PostgreSQL, BullMQ worker, production run tables, render queues, asset library and publishing drafts remain the infrastructure. Migration 0063 adds native agent definitions, immutable revisions, run snapshots, stage history, exclusive mode and bindings to agent tasks. It does not rewrite 0062, which may already be deployed.

Open Agent Studio in the owner navigation (/agents). Create one disabled agent per creator; select subscription, workflow, worker/audio where relevant, instructions, approved skills, approved memory, schedule and budgets. Edit a disabled definition to create a revision; existing runs retain their snapshot. Only owner-approved memory is persisted; no autonomous memory mutation. Manual or daily Vancouver time; daily schedule activation requires completed manual run of same revision and subscription. One daily run slot, one short per video run. Existing creator production-run uniqueness prevents a second native/legacy video run for the same day. Stop the overlapping legacy ChatGPT producer before opting into exclusive mode.

## Supported execution paths

STRATEGY, SCRIPT, IMAGE, H3_SHORT, LTX_SHORT. Research is optional and precedes creative stages. Video flow: planning → native image attachment → existing H3/LTX dispatch → exact indexed render → scoped review → platform-specific SEO → native thumbnail attachment → authoritative draft/cover/READY finalizer. Canonical references and exact output/job IDs are checked. LTX requires owner-selected creator audio with measured duration and a configured LoRA; native original output only, no automatic upscale. H3 can reserve one targeted corrective render for verified visual prompt defects; identity/equipment/technical or uncertain failures require owner review. READY means packaging verified and human review required, never automatic publishing. Long-video assembly, TTS, arbitrary custom DAGs and unsupported host capabilities are not advertised as implemented.

Owner dashboard shows run/stage/task history, schedule admission errors, reservations, pause/resume/stop. Pause prevents new stages; already started calls may finish. Stop cancels pending work and refuses new task writes; it does not guarantee terminating remote computation already started. Blocked video run pauses its underlying production run. Explicit same-day resume requires no failed/uncertain task replay.

## Budget and isolation

- Per-agent configurable task and image counts; global 12 tasks per Vancouver day and 2 active tasks. Active-slot contention waits; daily cap blocks. GPU default 2 reserved renders/day, AI_GATEWAY_DAILY_GENERATION_LIMIT can configure the ceiling; counts current native plan reservations and other submitted H3/LTX jobs. This is not a hardware-wide quota against concurrent manual rendering.
- Optional vidIQ requires explicit owner risk acceptance and query. One outlier search (5), optional one Short analysis (10). Global default 20 reserved credits/day, AI_GATEWAY_AGENT_VIDIQ_DAILY_LIMIT (0–100) changes the ceiling. Uncertain charges stay reserved. Host-reported receipts are validated for structure/call cost/time and source association; provider-side credits and ChatGPT subscription allowance cannot be independently hard-capped by Kemokem. No automatic Gemini or paid fallback.
- Exclusive hosted mode closes generic MCP invokes and ordinary request access, limits binary operations to active task claims and preserves signed diagnostic/task routes. Interactive mode and exclusive execution are mutually exclusive. This does not sandbox unrelated host tools or plugins. Connector must keep special tools available even when generic catalogue is empty.

## Release gates

This is a draft release candidate, not evidence of successful live production. Review and format new/changed source with repository tooling; verify typecheck/build/unit tests, targeted PostgreSQL lifecycle/security/reservation tests, full regression suite and browser E2E. Apply migrations through normal migrate service. Update the existing private Site (not a new plugin) and installed skill using AGENT_TASK_CONTRACT.md versions 1/2. Retain existing signing secret and identity. Site must expose task frames as actual images and pass claim on binary status/PUT. Verify diagnostic regression, actual claim→script→result, actual image native transfer, isolation denial, research receipts if opted in, H3/LTX render indexing and frame review, thumbnail and publishing readiness, same-ID deduplication and stop/pause. Test with real Ananya/Mehak creator configurations before enabling schedules. Do not simulate completion to satisfy release gates.

No automatic deployment or publish is part of this PR. If any required host capability fails, disable that workflow and report the exact blocker. Rollback: disable schedules, stop/finish active runs and resolve task uploads; restore interactive mode, revoke new scopes if appropriate, restore last verified Site/skill and application revision. Retain additive database tables. Never run legacy and native producers concurrently.
