# Agent Studio release contract

This branch starts the approved application implementation with a durable, signed creative task execution foundation. It is not the complete production engine. Do not merge or deploy until the remaining work and live acceptance are complete.

## Required remaining application work

1. Add agent definitions, creator binding, versioned workflows and skill snapshots, approved memory, persisted agent runs and task dependencies, scheduled and manual triggers, unique logical run slots, paused/stopped state and owner controls. Use existing PostgreSQL/BullMQ and production run tables; handle Vancouver daylight saving and avoid duplicate daily runs when the legacy producer is enabled. No new services.
2. Extend the versioned task registry with research, planning, image review, video review, thumbnail generation, SEO, analytics, correction and finalization. Every type must have an admission/result validator and an authorized handler. Prefer grouping compatible creative steps to reduce event overhead. Preserve source evidence, distinguish estimated metrics from actual CTR/retention, and never claim motion/audio/lip-sync from frames.
3. Implement creator-scoped canonical asset retrieval and reuse; snapshot approved references and skills; verify actual generated bytes and exact project/creator linkage. Keep locked identity immutable. Add read-only and upload-bound tools for every required asset. Require real triggered image generation and native upload before enabling it.
4. Reuse existing production.runStart, generation.h3/LTX, durable production plans, qualityReport, readiness and finalize contracts. Orchestrator should own backend writes and exact job identities, not ChatGPT waiting on GPU jobs. Handle offline queues, targeted index, existing jobs and superseded attempts. Reject unsupported long-video and TTS workflows until real capabilities exist.
5. Use existing FFmpeg/FFprobe technical inspection, exact output IDs and quality report binding. Connect external quality evidence to bounded correction and stage-specific retry without overriding observed defects. Preserve explicit owner review for continuous motion, spoken audio and lip-sync. Keep READY package-readiness, never automatic publication.
6. Add thumbnail/SEO/draft tasks and verified platform accounts, covers, drafts and media. Call authoritative finalizer; never simply change project status. Retain human publishing approval.
7. Enforce task-bound authorization for all autonomous operations, prevent bypass via the old broad interactive tools (dedicated restricted credential or equivalent host isolation), and enforce reservations, quotas and reconciliation. Existing hosted owner interactive functionality must remain. vidIQ usage is hard-enforced only if mediated through a trusted budget-aware integration; direct host plugin calls need clearly stated limitations. No paid fallback unless owner authorizes it.
8. Add production Agent Studio UI, per-agent configuration, schedules, capability checks, run/task histories, health, pause/resume/stop, budgets, memory/skills, workflow templates, actionable notifications, creator isolation and resource controls. Reuse existing design system and PWA.
9. Test schema migrations and rollback, all task types, atomic claims/leases, provider timeout/revocation, concurrent budgets, restart during generation/upload, expiry/refresh, duplicate delivery, stale/late completion, missing refs, cross-creator writes, renderer failures, draft finalization, and existing diagnostics and manual paths. Distinguish mocked callbacks from live Work runs. Run actual live end-to-end Ananya and Mehak/another niche, including character image transfer, vidIQ research, generation and readiness. Do not enable production until capability gates pass.
10. Coordinate application and existing private Site update; never create duplicate plugin, change sharing, rotate existing credentials unnecessarily, automatically publish, or add paid models/frameworks. Keep existing legacy producer as mutually exclusive fallback until acceptance.

The protocol and current routes are specified in AGENT_TASK_CONTRACT.md. The hosted connector is not in this repository; Codex must update its actual checkout and installed skill. Use the draft PR as the application source of truth, update contract and tests together when adding remaining types. Preserve the already verified diagnostics. No testing claims based on mere source inspection.

## Hosted pilot staging

Site version 21 is saved on the existing private Site and contains the version-1 task adapter. It adds no production exposure by itself. Leave `KEMOKEM_AGENT_TASK_PILOT` unset and leave `agents.subscribe` and `agents.execute` disabled on the live connector until a trusted restricted execution surface and the required acceptance tests are available. The flag is a rollout switch, not an execution isolation boundary. Version 20 remains the live diagnostic connector.

The native task upload tool derives its target from the claimed task and attaches the active claim to the binary PUT. It cannot prepare an unrestricted image upload. The existing interactive upload flow continues to use its own authorization.

Deploy only after the release checklist passes. Apply migration 0062 before enabling matching connector routes. Keep the existing private Site, signing secret and plugin identity. Release the matching production skill after the tool catalogue has been verified. Rollback disables the agent scopes and pilot flag, restores Site version 20, and rebuilds the prior application revision. Keep the additive migration tables for task history.
