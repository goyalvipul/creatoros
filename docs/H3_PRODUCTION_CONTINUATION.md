# Durable H3 production: first reliability patch

## Implemented in this patch
- Trusted H3 requests persist a QUEUED job even when the GPU is busy or temporarily unreachable. Existing authorization, quotas and media/project validation remain.
- Both H3 dispatcher entry points serialize H3 claims under a worker row lock, select the oldest non-paused job for that worker and check live ComfyUI queue plus active Kemokem jobs. Unknown/malformed queues are not free. Jobs remain queued until reachable and idle. This is not a global reservation across LTX/Qwen/other clients; future work must unify their dispatcher locks. No automatic retries of uncertain submissions.
- After H3 completion, request an indexed output-folder scan for the uniquely matched worker/scanner host and unique active folder ending in output. Refresh requests for missing final outputs at most every three minutes, for one day. Reuse existing library indexing/linking; no full org rescan. Ambiguous/unmapped output roots are explicitly recorded. Agent settle window and scan duration still apply; scan request is not index confirmation.
- Expose actual job error, worker, timestamps, progress, scan state and paused flag through generation.jobs; publishing.accounts includes brand ID and publishing preview is creator scoped for branded projects.
- No new scopes, migration or agent changes. Existing connector must preserve new result fields; no new input contract.

## Remaining end-to-end work (not delivered by this patch)
Durable production-run records and per-video stages (research evidence, planning, render queued, render running, scan/index, analysis, SEO, cover, review-ready, blocked, failed, cancelled), append-only event log, dashboard run history and pause/resume/cancel controls, authorization-bound postprocessing and account-independent per-platform draft packages. Need safe cancellation of specific prompt and explicit confirmation when interrupting a GPU; no machine-wide kill by default. ChatGPT scheduler owns trigger/research only; app should persist plans and own all subsequent execution. A separate postprocessing worker should observe indexed output and run authorized analysis then metadata/thumbnail steps, without waiting in a ChatGPT run. Existing Gemini calls are billable and must remain opt-in with quotas, idempotency and explicit cost authorization. No social account required to prepare an account-independent package; do not write to other creator accounts. Preserve manually edited drafts. Do not schedule/publish. Expose the durable run operations through MCP after implementation. Do not claim complete workflow until all stages verified.
