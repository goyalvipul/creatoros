# Dashboard machine monitoring (phase 1)
Replaces Today Home's duplicated stale Studio & workers list with a responsive production machine strip above the existing three-column dashboard. No creator filter for organization-wide resources; owner-only endpoint. Pulls live ComfyUI /queue and /system_stats concurrently per enabled worker, joins active generation job/project and reported progress, and existing paired scanner heartbeat/task records. Shows only measured memory and actual progress, not estimated whole-render percentages. Queue-free is not system idle. Unknown readings stay unknown; stale readings do not disable registered Windows task recovery. No prompt bodies, URLs or credentials returned.
Restart uses existing registered Windows scheduled-task service. The dashboard only offers it for a unique worker/device host match (hostname, Tailscale IP or scanner URL) and unique ComfyUI-labelled task. The dashboard restart re-resolves the unique saved worker/device/task association and calls the same requestWindowsTaskRestart service as Studio. It does not require ComfyUI connectivity, a free queue, fresh heartbeat, or a completed previous request. Explicit confirmation remains; busy/unknown queues warn about interruption. If the agent is offline, the request waits for reconnect. In-flight requests are reused by the existing service. No shell commands or automatic restart. Request acceptance is not restart completion. This is not an atomic lock shared with other clients or a guarantee against work started after the check; existing agent request handling is reused. No live restarts during tests.
No agent upgrade or migration needed for phase 1. GPU utilization, temperatures, watts, external process inventory and live per-node progress need new agent/ComfyUI telemetry. No persistent generation queue, new MCP operations or automatic notifications added. Run CI and test two live workers, stale/error behavior, mapping and an idle restart before release.
