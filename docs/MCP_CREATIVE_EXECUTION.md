# Creative execution authorization
Owner enables `production.execute` once per connector mode in Integrations > ChatGPT > Permissions > Production. It is deliberately not silently enabled for existing connections. The normal operation-specific permissions, owner authentication, org isolation, request IDs, replay protection and audit remain mandatory. No credential rotation or migration is needed. Existing narrower policy still works if the new scope is off.
Internal allowlist includes project/scene creation and editing, indexed media uploads, explicit editor saves, long-video editing, bounded H3/LTX/AutoGen/longscene generation, publishing draft/thumbnail and reply draft. Scheduled automation should submit generation.h3 directly, not h3.save. Trusted H3/LTX skip shared drafts and check worker queue. Existing available same-org library files can be used without creating a brand association in the new mode; verify creator identity before selecting them. Draft/thumbnail writes require a matching creator's social account and no non-draft state. External scheduling, rescheduling/cancellation, sending, billable analysis and render cancellation remain individually approved. Unknown ops fail closed.
Daily quotas count claimed requests including failures. Across H3/LTX/AutoGen/longscene combined, `AI_GATEWAY_DAILY_GENERATION_LIMIT` automatic generation submissions per Vancouver day (default 2); direct H3 total <=30s, LTX <=30s, <=2 MP, <=30fps, AutoGen one clip per request, longscene group <=30s. Other operation caps in creativeQuotas. Limits reject rather than request approval. These are conservative initial limits, not a persistent GPU reservation; AutoGen and longscene use their existing queue logic. No changes to previous pending requests; do not auto-execute or retry them.
references.image can now return a <=2 MiB JPEG preview of an original supported image up to 16 MiB, without mutating originals. The returned MIME/base64 contract is unchanged.
MCP v8 can continue using same 59 tools and 56 operations. Expected 30 scopes if all enabled. Catalogue approvalRequired still signals write lifecycle; conditionalProductionAuthorization advertises eligibility and invoke status is authoritative. If connector caches a fixed scope catalogue, refresh it. No tool schema changes.
Output attachment/assembly and publishing-item creation are not added here. Run CI and live smoke tests before relying on unattended production.

## Dedicated ChatGPT image upload root
Set `AI_GATEWAY_CHATGPT_UPLOAD_ROOT_ID` in the server .env to the UUID of the active Windows storage root whose exact path is D:\ChatGPT_Uploads. Empty disables the new exemption. A hosted owner credential with media.upload.image can prepare binary image sessions (or upload a supported Base64 image) without per-file approval only under this new dedicated-root rule. Existing creative/legacy authorization elsewhere is unchanged. The organization, active scanner/root, creator and project, checksum, MIME, size, request binding and replay checks still apply. Binary PUT rechecks the dedicated root before import. Audio and publishing approval policies are unchanged. The existing backend importer registers the file immediately; no separate scan request is necessary.
`AI_GATEWAY_DAILY_GENERATION_LIMIT` defaults to 2 and `AI_GATEWAY_DAILY_IMAGE_UPLOAD_LIMIT` defaults to 24; each accepts integers 0–1000 (0 blocks automatic requests, not an unlimited setting). Legacy narrower generation policy retains its own lower cap. Changes take effect after recreating the API container. Image quota counts claimed automatic image preparation and Base64 uploads together. Existing pending requests are not silently approved. The catalogue's conditionalProductionAuthorization field signals eligibility; the invoke response is authoritative. Connector-side fixed quotas must not override the configured backend cap.
