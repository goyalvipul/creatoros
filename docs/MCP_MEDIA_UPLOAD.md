# MCP media ingestion (draft rollout)
New scopes: media.upload.image, media.upload.audio. Disabled unless owner enables them per connector mode. Existing approval rules remain default; optional owner-configured hosted trusted production policy permits bounded operations.
New operations (catalogue is authoritative):
- media.roots {} lists indexed storage destinations and scanner state.
- media.uploadImage / media.uploadAudio: {rootId,brandId,projectId?,fileName,mime,base64}. Canonical base64, decoded max 5 MiB by default (set AI_GATEWAY_MEDIA_MAX_MIB to an integer 1–5 in the API process; restart to apply); png/jpeg/webp or wav/mp3/flac. POST /invoke with stable UUID requestId; returns PENDING. Approve in owner UI; GET /requests/:id returns result with fileId, assetId, versionId, sha256, size, tech. Use fileId in H3 library references, not worker filenames. Upload uses existing signed scanner endpoint, unique name, active indexed root, online paired scanner and brand/project validation. No arbitrary URL or filesystem path accepted. Do not retry uncertain uploads. If disk write succeeded but indexing failed, inspect destination manually. Existing request records retain immutable base64 input; review list suppresses base64. Keep payloads out of logs. 
- media.search {q?,kind?,brandId?,limit?=50,offset?=0}; brand filter matches linked logical assets; older untagged files need unfiltered search.
- media.detail {id}; metadata and recorded device/root states.
- gpu.queue {id}; existing live workerQueue service, returns free/busy/offline or other existing queue state. Read is advisory, not an atomic reservation.
Trusted production policy is off by default. Owner configures a creator, root, one or two workers and 1–2 daily projects/H3 attempts. Only projects.create/update, scenes.upsert, image/audio upload, generation.h3 and publishing.draft are eligible; individual scopes still required. Other operations remain pending. H3 requires branded library assets, 9:16, <=1 MP, <=5 segments, <=9s each and <=30s total, trimmed audio only, no video reference. H3 skips global editor draft and checks live queue; busy/offline is deferred (failed request, no automatic retry). Queue check is advisory, not atomic reservation against other clients. No output linking or assembly added. Policy claim is serialized on connection row, daily attempts count even on failure, hosted token rotation clears policy. Disabling stops new claims, not in-flight work. Catalogue retains approvalRequired=true as default, adds conditionalProductionAuthorization; invoke result is authoritative. Never treat COMPLETED as rendered or published.
Hosted connector: add exact typed tools based on live authorized /tools. Accept native file handles only if supported by host, retrieve bytes server-side through documented authorized mechanisms, or use explicit bounded base64 fallback (never invent file IDs or claim transfer support). No arbitrary URL fetch. No token changes. Test image/audio upload and H3 file resolution on an authorized scanner after deployment. No production writes during CI.

## Approval notifications
Integrations now shows owner-only pending requests at the top, polls every ten seconds and accepts /integrations?approval=<requestId> links. New PENDING requests enqueue one urgent, owner-targeted gateway.approval notification in the same transaction; retries and trusted executions do not send additional approval alerts. Existing PWA push settings and subscriptions apply. Quiet hours are bypassed for the short-lived approval event; explicit off/delivery settings still apply. Push content is generic, links open the authenticated review page, and approvals are never executed on notification click. Expired/reviewed/invalidated alerts are archived during the existing notification worker cycle, with TTL bounded by remaining request lifetime. Phone delivery requires VAPID configuration, worker, subscribed PWA and OS permission. Already displayed notifications cannot be remotely withdrawn reliably.

## Bounded Base64 transport
The schema, decoded-byte validation, media JSON budget and invoke HTTP body budget share the same configured cap. Non-media writes retain the 3,000,000-byte JSON budget. Existing signed scanner upload supports this size without an agent protocol change. The hosted MCP runtime and reverse proxy may impose lower limits; verify a real >2 MiB transfer before raising the hosted tool schema. The operation catalogue is authoritative. Base64 still resides in the request record; this change is not a streaming upload implementation, native ChatGPT file bridge, or durable production orchestrator.

## Server-side project image fallback
The existing Gemini AI worker now accepts project-scoped image requests without a long-video scene. `generation.imageCapabilities` requires the new `image.generate` scope; `generation.image {projectId,prompt,referenceFileIds,aspect,acceptBillable:true}` requires that scope and owner review (Gemini calls are billable). Existing AI settings, quotas and creator profile references apply. `generation.imageStatus {id}` uses generation.read and returns the actual completed AI asset IDs, not H3 file IDs. `media.importGeneratedImage {assetId,rootId,projectId,brandId}` uses media.upload.image and owner review, verifies same-project completed assets and imports up to 50 MiB server-side through the signed scanner path, without passing bytes through MCP. The original generated asset is retained. `production.runControl {id,action:pause|resume|stop}` requires generation.cancel and owner review; uses existing durable run controls. Do not automatically retry uncertain imports. Refresh hosted catalogue to expose these tools. These are not external binary upload sessions or a local ComfyUI image-generation workflow.
